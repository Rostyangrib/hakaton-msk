# План реализации Беспилотного коридора

## Ручная политика бортовых отказов для следующей сдачи

Неопределённость текущей автоматической допустимости: perception_health <0.5 независимо от AUTO, либо <0.9 при DEGRADED/REMOTE_REQUESTED; localization_confidence <0.5; communication_latency_ms >=2000 или packet_loss_pct_10s >=50. Это консервативные настройки команды, не официальные пороги ODD. Выход UNKNOWN без кодов PERCEPTION/LOCALIZATION/WIND; истинные нарушения GNSS/прочих условий сохраняют VIOLATED. После отказа: три новых измерения с возрастающим event_time и различными event_id, perception >=0.9, localization >=0.8, latency <1000 и loss <20. Дубли/старые события не восстанавливают здоровье, сценарий сбрасывает память.

Бортовой риск относится к текущему движению и группе текущей опасности при распределении поддержки; не переносится на будущую погоду. Без подтверждения текущего фрагмента и всего подъезда площадка не назначается. Невозможная ситуация остаётся диагностическим HOLD. Исходные критерии CONTINUE/REROUTE не изменены.

## Эксперимент уточнения дорожных классов и ODD

PARTIAL_BLOCK имеет приоритет над CONGESTED при подтверждённом сокращении полос любого типа источника. Для осадков: пространственный множитель (1-distance/coverage_radius)^2, доминирующая станция разрешает конфликт при доле >=2/3; иначе сохраняется диапазон UNKNOWN. Для текущей видимости при конфликте: три разных свежих измерения ниже порога и бортовая деградация (режим DEGRADED/REMOTE_REQUESTED, perception_health <0.9). Буфер max(10 м, 0.1 порога) при деградации даёт UNKNOWN, а не вымышленное нарушение. Эти ручные допущения проверяются на всех TRAIN и синтетике; labels используются исключительно офлайн. Правило CONTINUE/REROUTE неизменно. Реестр экспериментов привязывает полные метрики к коммиту runtime и SHA256 входов.

Python, без ML. Схемы имеют приоритет над текстовым ТЗ. Наблюдения описывают записанную ситуацию: рекомендации не считаются исполненными и не меняют будущие наблюдения. Ресурсы назначаются в текущем полном снимке; история не означает физическое резервирование.

После каждого этапа: компонентные и регрессионные проверки, обновление CHANGE_LOG.md и PROJECT_STATUS.md, проверка diff, отдельный коммит с русским сообщением и push в feature/corridor-algorithm. Это авторизовано пользователем.

## Зафиксированные настройки и обязательные правила

- Плановый маршрутный выбор только при remaining_m ≤ min(500, length_m). При допустимой текущей безопасности совпадение полных статического и динамического списков означает CONTINUE; различие означает REROUTE. Нет порога выигрыша или cooldown. Вне зоны — CONTINUE при допустимости; подтверждённая опасность впереди допускает ранний REROUTE; текущее нарушение ODD обрабатывается первым.
- Статический путь: положительное свободное время, масса, av_allowed, сооружения, номинальная скорость. Динамический: исключить CLOSED/UNKNOWN и подтверждённую несовместимость; скорость потока либо статическая × доля полос; множитель 1+(1-confidence); равные стоимости разрешать по идентификаторам.
- Затор: скорость <0.5 статического предела и occupancy ≥70% либо queue ≥100 м. Неактивность: свежая позиция ≤50 м от назначенного хаба, скорость ≤1 км/ч три последовательных шага; отсутствие телеметрии не означает завершение.
- Beta=(1+положительные)/(2+положительные+отрицательные), одно ограниченное свидетельство за шаг; положительные только при независимом подтверждении. FDIR: OUTAGE, DELAY, TIME_SKEW (1000 мс), FREEZE нескольких полей, BIAS/DRIFT по ≥3 сопоставимым точкам с порогом max(10 км/ч,3×MAD), PACKET_LOSS с учётом задержек/дублей, STALE и противоречия. Разные физические величины не сравниваются автоматически. Исключение trust<0.4 после ≥3 информативных шагов либо подтверждённый отказ сразу; восстановление после трёх согласованных шагов.
- Вес=trust×exp(-age/freshness_scale), freshness_scale=3 ожидаемых интервала показателя с учётом цикла RSU. confidence=agreement×(1-exp(-sum_independent_weights/0.5)); при недостатке 0.35. Не считать откалиброванной вероятностью без проверки. Статус источника и доверие — разные величины. Без обучаемой калибровки.
- ODD: VIOLATED при подтверждённом нарушении, COMPLIANT при подтверждении всех условий, иначе UNKNOWN. V2X по RSU и покрытию. wind_mps ниже бокового предела даёт верхнюю границу; превышение без направления означает неопределённость, код WIND не изобретать.
- Скорость WET 60, PARTIAL_BLOCK/WATER_FILM 40, очередь/затор и пограничная видимость [min,1.25min] 30; минимум дороги/ВАТС/надёжного RSU. FLOODED не означает допустимость проезда. Снижение скорости не снимает ODD.
- Площадки: совместное минимальное время подъезда с вместимостью, массой пути и площадки, достижимостью; равенство по ID. Поддержка ≤6: опасность, нарушение ODD, неопределённость, затем cargo_priority и ID; сохранить назначение при равенстве.
- HOLD в подтверждённой зоне ожидания; SAFE_STOP при небезопасном продолжении и допустимой площадке. Если нет пути/площадки: диагностический HOLD и доступная поддержка. Это протокольный fallback, не доказательство физической безопасности.
- Не включать исходные архивы, TRAIN/PUBLIC, временные файлы, логи, результаты прогонов. Runtime получает явно заданные пути и не читает labels, ноутбуки, эталонные таблицы.

## Ограничения готовности

Нераскрытая полезность действий и неоправданных переключений, пространственная семантика погоды, точная семантика поддержки, физическая допустимость последнего HOLD. Локальный балл не является официальным. Презентация — отдельное последующее задание. Каждый завершённый этап должен быть проверен, документирован, закоммичен и отправлен.

## Принятые доработки 28.09.2026

Доверие раздельно по показателям; Beta в окне 60 с. Дорожное восстановление: три новых сигнатуры, максимум 60 с. Память погодной неопределённости: 90 с и 5 км, три обновления прежних источников для снятия. V2X: цикл expected_period × число покрываемых сегментов; явная потеря >=20%, устойчивые задержки >=3 сообщений, отсутствие обновления >3 циклов. Map age увеличивается на возраст телеметрии. Устойчивая очередь >=100 м: три разных события за 60 с либо два независимых источника. Эти настройки не обучены и должны быть проверены полным сравнением.

Динамическая стоимость использует те же ситуационные пределы, что LIMIT_SPEED. SAFE_STOP допускается только при подтверждённом COMPLIANT всего подъезда, включая текущий фрагмент; UNKNOWN недостаточно. Поддержка: группа риска → cargo_priority → время до опасного продолжения → прежнее назначение → ID. Полные TRAIN являются регрессионной проверкой после анализа всех четырёх сценариев, а не независимым hold-out.

Восстановление доставки и отключённого показателя отделено от положительных Beta-голосов: три новых своевременных обновления без соответствующего сбоя. Истечение срока старого сообщения не считается новым свидетельством; счётчики восстановления используют новые event_id. Для повторной срочной сдачи заморожен runtime 6486a44; дальнейшая настройка переносится после приватного прогона. Архив называется Кариков Team2.zip и содержит пять файлов организатора, включая ранее подготовленную семистраничную презентацию.
