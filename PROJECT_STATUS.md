# Статус проекта

Этапы 0–10 реализованы. Этап 11: 28.09.2026 выполнен повтор текущей версии на всех четырёх TRAIN с подробным анализом; обнаруженные ошибки требуют доработки, безопасная готовность не объявляется. Текущая цель — устранение причин риска после приватной проверки.

Python без ML. Повторная проверка: 44 теста успешны (40 runtime-регрессий и четыре теста офлайн-подсчёта). Правило CONTINUE/REROUTE сохраняет полное сравнение путей в зоне remaining_m ≤ min(500,length_m), без cooldown или порога выигрыша.

Актуальные метрики и разбор: docs/TRAIN_CURRENT_ANALYSIS.md. Исторический отчёт: docs/TRAIN_QUALITY_PRELIMINARY.md. Высокая валидность интерфейса не означает правильность оценок. Все 2160 пакетов текущего TRAIN обработаны; 31 runtime-файл побайтово совпадает с source.zip технической сдачи. Это локальный последовательный Python-прогон, не новый Docker-тест.

Этап 12: текущий технический пакет подготовлен. Автономный linux/amd64 образ собран, экспортирован и проверен. PUBLIC-101/102: 540/720 ответов, все валидны, EOF код 0, максимум ответа 1.40 с, превышений 2 с нет. Проверены лимиты 8 CPU/16 ГБ, отсутствие сети/GPU, read-only runtime. SHA256 31 runtime-файла совпадает с source.zip. Архив «Кариков Team.zip» содержит четыре технических файла. Презентацию пользователь добавляет самостоятельно как presentation.pdf в корень архива.

Ограничения: неизвестны полезность действий и определение необоснованных переключений; пространственная семантика погоды, точная семантика поддержки и физическая допустимость последнего HOLD. Confidence — алгоритмическая эвристика, не доказанно откалиброванная вероятность. Runtime не читает labels и не обращается в сеть.

Следующий шаг: исправления по плану в актуальном отчёте, начиная с ODD/погоды и возраста карты; затем пропуски заторов и диагностика отказов. После изменений — полный TRAIN, полный повтор PUBLIC и новая Docker-проверка. Детализация четырёх приватных эпизодов пока отсутствует.

## Доработка после приватной проверки — этап A, 28.09.2026

Разделено доверие к доступности, скорости, очереди и трём погодным показателям. Подтверждение OPEN больше не является положительным свидетельством скорости. Сокращены ложные PACKET_LOSS при задержках и смене типа сообщения. Оценка загрузки независима от доступности: устойчивая очередь >=100 м допускает CONGESTED без подмены скорости рекомендацией RSU. Добавлены три независимых обновления для снятия дорожного предупреждения, погодная память 90 с/5 км и проверка обслуживания V2X с учётом цикла покрытия, задержек и явной потери пакетов. Возраст карты приведён к моменту решения. Настройки являются ручными допущениями.

Проверки: 51 unittest успешно, включая семь новых регрессий; git diff --check без ошибок. Полные измерения качества новой версии ещё не выполнены; улучшение приватного балла или отсутствие физических аварий не утверждаются. Правило сравнения маршрутов не изменено. Следующий этап: ситуационная стоимость маршрута, приоритет поддержки по времени до опасности и проверка полного подъезда к площадке.

## Доработка после приватной проверки — этап B, 28.09.2026

Общие ситуационные пределы скорости включены в команды и стоимость динамических рёбер; FLOODED исключается. При равных группе риска и cargo_priority поддержка учитывает время до первого проблемного продолжения, затем прежнее назначение и ID. Подъезд к SAFE_STOP теперь требует COMPLIANT на текущем фрагменте, всём пути и целевом сегменте, допустимой массы и проезда; стоимость включает остаток текущего сегмента. Независимый финальный контроль проверяет те же условия. Если подтверждения нет, остаётся согласованный диагностический HOLD с доступной поддержкой. Точная точка площадки отсутствует в справочнике: доступен только segment_id.

Проверки: 55 unittest успешно, включая стоимости WATER_FILM/очереди, неизвестный будущий ODD, закрытый текущий фрагмент и порядок поддержки. Начальная неуспешная попытка тестирования имела два FileNotFoundError из-за неверного CORRIDOR_REFERENCE; после указания внешнего исходного справочника все проверки успешны. Полное сравнение качества следует далее. Правило CONTINUE/REROUTE не изменено. Docker-проверка поддерживает отдельный тег сравнения, сохраняя старый final.

## Регрессия первого сравнения и исправление — этап C

Первый полный TRAIN-002 промежуточной версии c6adb9a показал регрессию F1 дорог 0.9935 → 0.9878: лишние UNKNOWN из-за проверки weight >=0.7 вместо отдельного доверия доступности. Восстановлен смысл прежнего порога: отдельное trust(availability) >=0.7 и положительный свежий вес. Источник с нулевым доверием доступности не считается вторым подтверждением, даже если его скорость допустима. Добавлены две регрессии.

Все 60 текущих unittest проходят. Промежуточные результаты (61 завершённый синтетический случай, два TRAIN и оба PUBLIC) сохранены вне Git в output/comparison/pilot-*. Первый Docker-прогон под конкурирующими задачами превышал 2 с: 11 ответов в каждом PUBLIC; эти измерения не удалены. После исправления выполняются заново все TRAIN/83 синтетических случая; Docker будет проверен без параллельных прогонов. До их завершения качество новой версии не объявляется подтверждённым.
