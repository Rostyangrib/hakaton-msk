# Аудит безопасности управления

Дата: 28 сентября 2026. Базовая версия: `8768465` (Team3).

Проверены техническое задание, паспорт данных, машинные контракты, справочники,
цепочка State → Trust → Fusion → ODD → Router → Resources → Guard и прежние отчёты.
Содержимое справочников и JSON-контрактов в репозитории совпадает с добавленным
набором данных; различается только форматирование JSON.

Логи четырёх скрытых аварий не предоставлены. Ниже описаны воспроизводимые
дефекты программы, а не установленная причина каждого скрытого эпизода.

## Исправленные дефекты

| Дефект | Почему опасен | Исправление |
|---|---|---|
| Исключение сообщения CLOSED из-за двух сообщений OPEN | Настоящее закрытие можно объявить ложным, понизить доверие к источнику до нуля и разрешить проезд | Свежее сообщение о закрытии сохраняет запрет на подтверждение доступности, если основанием исключения было противоречие. Независимые отказы целостности/времени по-прежнему учитываются |
| Будущий ODD=UNKNOWN разрешался в динамическом маршруте | Недостаток данных трактовался как разрешение ехать | Для всех рёбер требуется COMPLIANT; независимая проверка в финальном guard |
| Погода будущего сегмента проверялась только в середине | Небольшая зона затопления или отсутствие покрытия на въезде оставались незамеченными | Проверяются концы сегмента, пересечения с границами зон станций и внутренние точки каждого интервала. Результат кешируется на пакет |
| Пространственное доминирование станции сужало диапазон дождя | Применимое опасное показание исчезало из ODD | Отдельный полный `safety_ranges` используется для допуска движения; точечная погодная оценка остаётся отдельной |
| Ветер, поверхность и скоростная видимость брались из центральной оценки | Медиана/голосование могли скрыть сильный ветер, затопление или потребность снизить скорость | Для безопасности используются верхняя граница ветра, наиболее опасная применимая поверхность и нижняя граница видимости |
| REROUTE вытеснял LIMIT_SPEED | Ограничение влияло лишь на стоимость маршрута, но не на команду автомобилю | Если текущий фрагмент или ребро объезда требует отдельного скоростного ограничения, выбирается HOLD либо проверенный SAFE_STOP; запрашивается доступная поддержка |
| Финальный guard не проверял текущий av_allowed и величину скорости | Ошибочное промежуточное решение могло пройти контроль | Повторная проверка совместимости текущего сегмента, ODD, затопления, обязательности и верхней границы ограничения скорости |
| Свежий V2X считался исправной услугой при уже найденном коммуникационном отказе | Продолжение движения до полного исключения RSU | PACKET_LOSS/DELAY/TIME_SKEW/STALE/BYZANTINE/OUTAGE не позволяют подтвердить услугу по одному свежему сообщению; независимый исправный RSU остаётся допустимым |
| Одно сообщение неподвижного автомобиля засчитывалось трижды | Потеря телеметрии у хаба превращалась в NO_ACTION и обходила ODD | Три разных сообщения с возрастающим временем; дополнительно проверяется направленный подъезд к хабу назначения |
| Весь сегмент с площадкой считался зоной стоянки | Автомобиль за километры от площадки мог получать HOLD вместо явного назначения остановки | Наличие площадки на дороге не доказывает нахождение на ней. SAFE_STOP проходит обычное распределение вместимости и проверку подъезда |

Правило сравнения полных статического и динамического путей и граница 500 м
сохранены внутри множества допустимых вариантов. Проверки безопасности имеют
приоритет над выбором действия. Пороговые значения ODD и формат ответа не менялись.
Runtime не читает labels и не содержит специальных правил по TRAIN/PUBLIC ID.

## Проверка

Добавлен `tests/test_safety_regressions.py`: 16 проверок, включая 14 контрпримеров,
нормальную доставку/сухой объезд и массовое нарушение видимости у 72 автомобилей.
На копии исходного runtime из Git HEAD получены 14 проваленных проверок, без ошибок
запуска тестов. На исправленном runtime все 16 проходят.

Все 91 unittest, включая интеграционные тесты на TRAIN-001, прошли.
`tools/demo.py` также проходит: CONTINUE в норме, корректный REROUTE при закрытии,
LIMIT_SPEED 30 при заторе, ограничения площадок и шести операторов.

Проверка выполнена локальным Python 3.12 из доступного runtime. TRAIN и PUBLIC
запускались отдельными процессами на одном хосте; измерения времени включают
конкуренцию за ресурсы. Docker daemon в этой сессии недоступен, поэтому сборка и
приёмка обновлённого образа linux/amd64 с Python 3.13 не подтверждены. Старый образ
Team3 не содержит эти исправления и не должен считаться обновлённой поставкой.

Полные результаты TRAIN/PUBLIC и ограничения проверки будут записаны после
завершения прогона в `results/safety-audit`, `results/safety-analysis` и
`results/safety-public`.

Повторение проверки:

```powershell
$env:CORRIDOR_REFERENCE=(Resolve-Path 01_reference).Path
python -m unittest discover -s tests -v
python tools/evaluate.py --data . --out results/safety-audit --details
python tools/train_analysis.py --data . --results results/safety-audit --out results/safety-analysis
python tools/replay_suite.py --repo . --data . --out results/safety-public
```

## Границы результата

Более осторожная политика может увеличивать ожидание и снижать логистическую
полезность. HOLD вне подтверждённой зоны ожидания остаётся диагностическим
резервным действием при невозможности безопасного подъезда, а не доказательством
безопасной физической остановки. Поддержка ограничена шестью операторами;
неназначенный запрос не выдаётся за состоявшееся сопровождение.

Полный будущий маршрут проверяется по доступным сейчас наблюдениям и
пересчитывается каждый пакет. Это не прогноз погоды на время фактического прибытия.
Покрытие станции не гарантирует отсутствие ненаблюдаемой локальной опасности.
Нет симулятора исполнения команд: успешный прогон не доказывает фактическую
доставку груза и не гарантирует нулевые аварии на скрытом наборе.
