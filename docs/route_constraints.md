# Измеряемые переменные и ограничения, влияющие на выбор пути

## 1. Назначение документа

Перечень основан на входной JSON-схеме, профилях ODD, справочниках дорог и правилах оценки кейса «Беспилотный коридор». При расхождениях с текстовым ТЗ приоритет имеет JSON, согласно уточнению организатора.

Здесь разделены:

- **Обязательные ограничения:** заданные пороги ODD и условия допустимости маршрута.
- **Факторы стоимости:** показатели, влияющие на время, очередь и предпочтительность пути без установленного универсального запрета.
- **Факторы достоверности:** показатели, определяющие, можно ли доверять оценке участка.

Числовые границы типов в JSON-схеме не следует путать с порогами безопасности. Например, допустимый формат `speed_kmh` до 160 не означает разрешение ехать 160 км/ч.

Состав входных сообщений подробно описан в [source_data.md](source_data.md).

## 2. Точные пороги ODD

Источник: `01_reference/09_odd_profiles.json`. Профиль определяется отдельно для каждого автомобиля по `odd_profile_id`.

| Проверяемая переменная / условие | ODD-A | ODD-B | ODD-C | ODD-D | Условие соответствия |
|---|---:|---:|---:|---:|---|
| Видимость `visibility_m`, м | минимум 70 | минимум 100 | минимум 150 | минимум 80 | Значение ≥ минимума |
| Дождь `rain_level` | максимум 3 | максимум 2 | максимум 2 | максимум 3 | Значение ≤ максимума |
| GNSS `gnss_quality`, 0–1 | минимум 0,55 | минимум 0,70 | минимум 0,80 | минимум 0,65 | Значение ≥ минимума |
| Возраст бортовой карты `map_age_min`, мин | максимум 1440 | максимум 360 | максимум 240 | максимум 60 | Значение ≤ максимума |
| Боковой ветер `max_crosswind_mps`, м/с | максимум 22 | максимум 18 | максимум 16 | максимум 20 | Боковой ветер ≤ максимума; измерение неоднозначно — см. ниже |
| Наличие V2X | Не обязательно | Обязательно | Не обязательно | Обязательно | Для B и D нужна доступная V2X-связь |
| Тип сооружения `structure` | open, bridge, tunnel | open, bridge, tunnel | open, bridge | open, bridge, tunnel | Тип входит в разрешённый список |

Равенство порогу допустимо по смыслу полей `min_*` и `max_*`.

Шкала дождя: 0 — нет; 1 — слабый; 2 — умеренный; 3 — сильный. `precipitation_mm_h` не заменяет `rain_level`: обязательный ODD-порог установлен именно для категории дождя.

### 2.1. Как пороги влияют на путь

| Переменная | Откуда приходит | Влияние на выбор пути |
|---|---|---|
| `visibility_m` | Метеостанция | Участки с видимостью ниже порога не соответствуют погодному условию ODD автомобиля; следует искать допустимый объезд либо выбирать безопасное действие |
| `rain_level` | Метеостанция | Участки с дождём выше порога не соответствуют ODD; для B и C уровень 3 превышает предел |
| `gnss_quality` | Телеметрия автомобиля | Низкое качество выводит автомобиль за соответствующий порог ODD; само по себе не указывает, какой другой участок восстановит GNSS |
| `map_age_min` | Телеметрия автомобиля | Превышение возраста карты нарушает ODD; смена маршрута сама по себе карту не обновляет |
| Доступность V2X | Сообщения RSU, диагностика, связь автомобиля, справочник зон | Для B и D недоступная связь нарушает ODD; маршрут должен учитывать покрытие и актуальную работоспособность связи |
| Боковой ветер | В событии есть только `wind_mps` | Порог задан, но для точного сравнения не хватает направления / отдельного измерения бокового ветра |
| `structure` | Справочник сегментов | Для C туннели вне ODD; при подборе допустимого маршрута такой сегмент исключается |

**Важные границы интерпретации:**

- Наличие у сегмента `v2x_zone` не доказывает, что V2X сейчас работает. В контракте нет единого числового критерия вида «V2X недоступна при задержке > X мс».
- Профиль задаёт `max_crosswind_mps`, а погодное событие — `wind_mps` без направления. Нельзя объявлять их эквивалентными без дополнительного правила. В выходном перечне ODD-кодов также нет отдельного кода WIND/CROSSWIND. Это требует уточнения у организатора.
- Отсутствие свежего измерения не доказывает ни соблюдение, ни нарушение порога: при недостатке данных нужна оценка неопределённости.
- Удалённая поддержка не делает превышенный ODD-порог соблюдённым и не снимает ограничения массы, закрытия и запрета движения.
- Для будущих участков используются доступные текущие оценки; нельзя брать будущие пакеты, чтобы заранее узнать погоду или отказ.

Пример: при видимости 90 м условие видимости выполняется для A и D, но нарушается для B и C. Это только одна проверка; итоговый ODD зависит от остальных условий.

## 3. Масса, закрытия и доступность сегментов

Эти ограничения включены в правила допустимости полного маршрута `REROUTE`.

| Переменная / условие | Источник | Проверка | Результат нарушения |
|---|---|---|---|
| Полная масса `gross_mass_t` | Справочник автомобилей | `gross_mass_t ≤ weight_limit_t` каждого сегмента | Сегмент не допускается в маршрут |
| Предел массы `weight_limit_t` | Справочник сегментов | Сравнение с полной массой ВАТС | Объезд по сегментам с подходящим пределом |
| `av_allowed` | Справочник сегментов | Должно быть 1 | При 0 сегмент не допускается в маршрут |
| Состояние сегмента | Оценка по детекторам, камерам, RSU, двойнику | На момент решения сегмент не должен быть `CLOSED` | Закрытый сегмент не допускается в маршрут |
| Доступность полос | `lane_count_open_estimate`, `lane_status`, `lane_count_open`, `closure_state` | Наблюдения используются для оценки состояния участка | Подтверждённая полная блокировка исключает участок; частичная влияет на скорость и пропускную способность |

Масса здесь справочная, а не показание весового датчика: отдельное событие взвешивания в контракте не задано.

Пример: автомобиль массой 42 т нельзя направлять на сегмент с пределом 40 т, даже если этот путь быстрее.

`CONGESTED` и `PARTIAL_BLOCK` не означают автоматический запрет всего сегмента. `UNKNOWN` — недостаток знания о состоянии: политика его использования должна учитывать риск. Требование «all segments exist» относится к существованию идентификатора в графе; его нельзя путать с оценочным состоянием `UNKNOWN`.

## 4. Скорость и загрузка дороги

| Переменная | Источник | Как влияет | Обязательный универсальный порог |
|---|---|---|---|
| `speed_kmh` автомобиля | Телеметрия | Текущее движение и оценка времени до следующего узла | Универсального порога выбора пути нет |
| `speed_kmh` потока | Детекторы и видеоаналитика | Оценка времени проезда; низкая скорость может сделать объезд выгоднее | Порог «ниже X — обязательно объезд» не задан |
| `speed_limit_kmh` | Справочник дороги и сообщение двойника | Ограничение скорости влияет на возможное время проезда | Значение конкретного участка, а не единый предел |
| `nominal_max_speed_kmh` | Справочник автомобиля | Характеристика ВАТС для оценки достижимой скорости | Значение конкретного автомобиля |
| `advisory_speed_kmh` | RSU | Рекомендация скорости; учитывается с надёжностью источника | Не является автоматически принятой командой |
| `flow_vph` | Детекторы и видеоаналитика | Показывает интенсивность транспортного потока | Порог обязательного запрета не задан |
| `capacity_vph` | Справочник сегментов | База для оценки перегрузки и эффекта добавленных ВАТС | Не задано правило «поток выше capacity — сегмент CLOSED» |
| `occupancy_pct` | Детекторы и видеоаналитика | Признак плотности / занятости зоны наблюдения | Порог затора не задан |
| `queue_estimate_m` | Детекторы, камеры, RSU | Очередь увеличивает задержку и может повысить привлекательность объезда | Максимальная допустимая очередь не задана |
| Число открытых полос | Дорожные наблюдения и двойник | Сокращение полос уменьшает доступную пропускную способность | Формула пересчёта мощности не задана |
| `acceleration_mps2` | Телеметрия | Помогает распознавать замедление и характер движения | Порог запрета маршрута не задан |

Для сравнения маршрутов допустимо оценивать время участка по длине и ожидаемой скорости, дополняя его задержкой в очереди. Нельзя автоматически подставлять скорость одного ВАТС как среднюю скорость всей дороги. При нулевой скорости простая формула `длина / скорость` неприменима.

Отношение `flow_vph / capacity_vph` — возможный показатель загрузки, а не готовое контрактное правило закрытия. Порог выбора объезда и модель очереди — параметры решения, которые следует проверять на обучающих сценариях.

## 5. Другие погодные и бортовые показатели без заданных порогов

| Переменная | Источник | Возможное влияние | Что установлено контрактом |
|---|---|---|---|
| `precipitation_mm_h` | Метеостанция | Дополняет оценку дождя и риска | Отдельного порога ODD в мм/ч нет |
| `road_surface` | Метеостанция | DRY, WET, WATER_FILM, FLOODED помогают оценивать риск участка | Нет таблицы обязательных действий или запретов для каждого значения |
| `air_temperature_c` | Метеостанция | Дополнительный погодный контекст | Температурных порогов ODD нет |
| `localization_confidence` | Телеметрия | Низкая уверенность ухудшает надёжность положения и выбора действия | Порог ODD для этого поля не задан; не заменяет `gnss_quality` |
| `perception_health` | Телеметрия | Деградация восприятия влияет на безопасность движения | Обязательный числовой порог не задан |
| `autonomy_state` | Телеметрия | DEGRADED / REMOTE_REQUESTED требуют учитывать состояние автономной системы и поддержку | Единой обязательной таблицы «режим → действие» нет |

Например, `FLOODED` — серьёзный сигнал риска, но в файлах контракта он не определён как автоматический эквивалент дорожного состояния `CLOSED`. Состояние дороги и действие должны быть обоснованы совокупностью данных.

## 6. Задержка, связь и достоверность наблюдений

Эти переменные обычно влияют на путь косвенно: изменяют доверие к сведениям о дороге, погоде и положении ВАТС.

| Переменная | Что оценивается | Влияние на решение |
|---|---|---|
| `received_time − event_time` | Задержка доставки при исправных часах | Старое наблюдение не должно без проверки перезаписывать более новое |
| `communication_latency_ms` | Задержка связи автомобиля | Надёжность связи и возможность поддержки |
| `packet_loss_pct_10s` | Потери пакетов автомобиля | Полнота телеметрии и качество связи |
| `network_packet_loss_pct` | Потери инфраструктурного компонента | Надёжность его потока данных |
| `source_clock_offset_ms`, `time_sync_offset_ms` | Рассогласование часов | Надёжность времени измерения |
| `last_heartbeat_age_sec` | Время без сигнала работоспособности | Возможный отказ / потеря доступности источника |
| `snapshot_age_sec`, `source_updated_time` | Возраст данных двойника | Устаревшее состояние дороги может быть неверным |
| `signature_valid` | Корректность подписи RSU | Проверка сообщения; корректная подпись не доказывает истинность содержания |
| `self_reported_confidence` | Уверенность самого источника | Один из признаков для оценки доверия, не окончательная оценка |
| `status` диагностики | OK, DEGRADED, NO_HEARTBEAT | Признаки исправности инфраструктуры |
| `cpu_load_pct`, `memory_used_pct` | Загрузка компонента | Возможные причины задержки и деградации |
| Номера сообщений, `event_id`, `duplicate` | Пропуски, повторы, порядок доставки | Предотвращение повторного учёта и ложного подтверждения |

**Для этих показателей контракт не задаёт универсальных числовых порогов запрета маршрута.** Например, нельзя представить «задержка > 100 мс» или «потери > 5%» как требование организатора. Такие пороги, если используются, относятся к вашей модели и должны быть отдельно обоснованы.

`watermark_lag_sec = 60` — параметр работы с потоком событий, а не универсальный срок годности всех измерений. `max_map_age_min` из ODD относится к бортовой карте автомобиля; это другой показатель, чем возраст снимка двойника.

Порог низкого итогового `confidence` для выбора осторожного действия также не задан. Неопределённость нельзя трактовать как подтверждённую безопасность участка.

## 7. Загрузка хаба и транспортная задача

| Переменная | Источник | Влияние на путь / действие |
|---|---|---|
| `queue_vehicles` | HUB_STATUS | Очередь в пункте назначения увеличивает ожидание |
| `capacity_vehicles` | HUB_STATUS и справочник хабов | Вместимость используется для оценки перегрузки |
| `capacity_used_pct` | HUB_STATUS | Степень загрузки; универсальный порог смены маршрута не задан |
| `service_rate_vph` | HUB_STATUS | Скорость обслуживания определяет прогноз ожидания |
| `estimated_wait_min` | HUB_STATUS | Оценка задержки доставки |
| `accepting_new_arrivals` | HUB_STATUS | Недоступность приёма влияет на план прибытия и удержание в допустимом месте |
| `cargo_priority` | Телеметрия / справочник | Приоритет распределения ресурсов и снижения задержек; 1 — высший |
| `deadline_offset_min` | Справочник заказов | Срок доставки относительно временной основы заказа / сценария |
| `penalty_per_min` | Справочник заказов | Стоимость опоздания |

Очередь хаба влияет прежде всего на ожидаемое время и действия, а не обязательно на геометрию маршрута. Хаб назначения нельзя произвольно заменять: валидный REROUTE должен завершаться в заданном destination HUB. Срок и приоритет не разрешают нарушать массу, ODD или закрытия.

## 8. Ограничения безопасной остановки и поддержки

Это ограничения альтернативного назначения и ресурсов, а не обычного маршрута к хабу.

| Показатель | Проверка |
|---|---|
| Масса ВАТС `gross_mass_t` | Не превышает `max_vehicle_mass_t` площадки и `weight_limit_t` её дорожного сегмента |
| Состояние сегмента площадки | Не CLOSED |
| Число одновременных назначений | Не превышает `capacity_vehicles` площадки |
| Число одновременных назначений удалённой поддержки | Не более 6 |
| `has_remote_link` площадки | Справочная возможность связи; нет отдельного явно сформулированного запрета SAFE_STOP на площадке без связи |
| `session_setup_sec` | В пуле поддержки указано 20 с; это время установления сеанса, не дорожный порог |

Точные параметры площадок:

| Площадка | Сегмент | Вместимость | Максимальная масса, т | Удалённая связь |
|---|---|---:|---:|---|
| SS-01 | S005 | 4 | 44 | Да |
| SS-02 | S013 | 6 | 44 | Да |
| SS-03 | S021 | 5 | 44 | Да |
| SS-04 | S027 | 7 | 44 | Да |
| SS-05 | S034 | 4 | 44 | Да |
| SS-06 | S042 | 5 | 44 | Да |
| SS-07 | S054 | 3 | 40 | Нет |
| SS-08 | S062 | 6 | 40 | Да |
| SS-09 | S075 | 3 | 44 | Нет |
| SS-10 | S083 | 4 | 44 | Да |

Входного отдельного события оперативной занятости площадки нет. Нужно вести учёт собственных назначений по правилам решения; нельзя придумывать доступные показания датчика занятости. Формальное отсутствие проверки пути до площадки в перечисленных метриках не означает физической достижимости: при планировании нужно учитывать направление графа и допустимые подъезды.

## 9. Геометрические условия маршрута

Хотя это не измеряемые переменные, без них маршрут невалиден:

1. Все идентификаторы сегментов существуют.
2. `route_segment_ids` содержит полный направленный путь **после текущего сегмента**.
3. Первый сегмент начинается в `to_node` текущего сегмента.
4. Соседние сегменты связны: конец предыдущего совпадает с началом следующего.
5. Каждый сегмент разрешён для ВАТС, совместим с массой и не CLOSED.
6. Последний сегмент заканчивается в узле назначенного хаба.

`segment_id` и `offset_m` телеметрии определяют текущее положение. Длина сегмента нужна для расчёта оставшегося пути. Сам текущий сегмент не добавляется в выдаваемый полный путь после него.

## 10. Порядок применения ограничений

1. Определить автомобиль, его профиль ODD, массу, положение и назначение.
2. Проверить свежесть наблюдений и доверие к источникам.
3. Оценить дорожные и погодные условия по сегментам.
4. Проверить ODD автомобиля. Если проблема относится к самому автомобилю — например, старая карта — не считать объезд достаточным исправлением.
5. Для допустимого автономного маршрута исключить запрещённые, закрытые, несовместимые по массе и профилю участки.
6. Среди оставшихся путей сравнить ожидаемое время, очереди, загрузку и риск; учесть назначение других ВАТС.
7. Если допустимого пути нет или движение небезопасно, выбрать предусмотренное контрактом безопасное действие с проверкой ресурсов.
8. Проверить полноту и связность выдаваемого маршрута.

Нарушение ODD не означает универсальное правило «всегда REROUTE». Возможны ограничения скорости, HOLD, SAFE_STOP и запрос поддержки в зависимости от причины и ситуации. Само по себе снижение скорости не устраняет нарушение порога видимости или возраста карты.
